# 上游调用前扩展注册表

## 说明

plugin 定义进程内扩展链，在推理请求读取响应缓存或联系上游供应商之前同步执行。它用小型命名接口隔离扩展实现与网关进程。这里不是动态加载器：不执行脚本，不扫描包，不提供安装接口，不持久化扩展，也没有进程隔离。

## 对外接口

- `Call` 是数据面传给扩展的只读调用上下文，包含操作名、公开模型和请求路径，不携带请求正文或凭据。
- `Decision` 包含放行/拒绝、HTTP 状态、稳定错误码、客户端消息和响应头。零值表示继续处理；`Refuse` 为真时，数据面跳过缓存读取与上游发送，并按目标协议写响应。
- `Extension` 要求稳定非空的 `Name()` 和 `BeforeUpstream(Call) Decision`。扩展同步执行，可以自行产生副作用，注册表无法回滚。
- `New() *Registry` 返回空注册表；Registry 零值同样可直接使用。
- `Register(ext) error` 拒绝 nil 注册表、nil 扩展、空名字和重名。失败不改变顺序或索引；成功后按确定顺序追加。
- `Names() []string` 按登记顺序返回副本；nil 注册表返回 nil。
- `Invoke(name, call) (Decision, error)` 只执行指定名字。名字不存在或注册表为 nil 时返回错误，不会改调其他扩展。
- `Run(call) Decision` 按登记顺序执行快照。响应头逐步合并，后值覆盖同名先值；第一条拒绝立即停止，返回该扩展的状态、错误码、消息以及截至该扩展积累的全部头。空或 nil 注册表放行。

internal/gateway 创建并注册扩展，internal/dataplane 执行扩展。本包不登记 HTTP 路由。

## 内部核心实现

Registry 用一个互斥锁保护有序扩展切片、平行名字切片和名字映射。Register 持锁同时修改三者，Names 持锁复制，Invoke 持锁取出单个实现后解锁再调用。Run 也先复制有序切片再执行回调，因此回调可以登记扩展而不会死锁，并且执行途中新增的扩展只影响后续请求。

响应头使用新映射累积。拒绝会保留之前的头，并允许拒绝扩展覆盖同名值。放行决定中的状态、错误码和消息会被忽略；全部放行后只返回合并头。扩展实现必须自行保证并发安全、时延有界、策略确定，并避免不可回滚操作或秘密泄露。

### 测试依赖

`registry_test.go` 覆盖零值、输入校验、稳定顺序、名字副本、精确查找、响应头覆盖和首次拒绝终止。运行 `go test ./internal/plugin -count=1`；不依赖外部服务。

## 源码职责与入口

- `registry.go` 包含全部生产契约与同步逻辑：Call、Decision、Extension、Registry、New、Register、Names、Invoke、Run。
- `registry_test.go` 提供确定性测试扩展，验证注册表和扩展链行为。
