# 浏览器全量测试设计方案

日期：2026-10-11（Asia/Shanghai）。设计基线：Git `082da5e`。本文是执行方案，不是已通过的测试报告。

> 最新执行规则（优先于本文旧的失败后继续策略）：以 [英文方案](../en/browser-full-test-plan.md) 的逐任务验收契约为准。一个角色保持会话，每次只做一个任务，立即测试并验收，全部必需证据及清理义务通过后才做下一项。任何错误、超时、证据不足、会话异常或清理失败立即停止整个验收运行，其他角色及独立任务也不继续；只允许安全留证和本轮资源清理。获准恢复后先复验失败任务及受影响依赖，禁止自动重试写入、自动重新登录或削弱断言。符合预期且验证无副作用的拒绝场景不算失败。本文下方“独立任务继续”及 SSO／SCIM 失败互不阻塞的旧规则不再适用。本轮仅修订方案，连续任务执行器尚未实现或执行。

## 1. 目标与全量定义

从不同真实用户的任务出发，验证页面操作经过真实后台、持久化和网关数据面后得到正确结果。页面可打开、接口返回 200 或按钮变色均不能独立证明业务成功。

本轮范围包括控制台、聊天工作区、模型与协议、权限与归属、路由、护栏、额度与计费、企业设置、文档站和兼容入口。全量指当前实现能力的完整清单，不指所有外部供应商或全部输入组合。

执行前生成四份清单：

1. 页面及实际导航入口清单，包含页签、详情、弹窗、旧地址和动态文档 URL。
2. 身份及成员关系清单，区分平台角色、组织角色、团队角色与资源归属。
3. 用户可执行动作和配置对应的数据面效果清单。
4. 用例与页面、角色、动作、接口、业务结果之间的覆盖映射。

当前静态发现 45 个 `page.tsx` 路由模板；其中 `/docs/[[...slug]]` 必须展开为实际文章，不得作为字面 URL 测试，也不得因包含 `notFound()` 就归类为退役。已确认 `/router-settings` 和 `/models-and-endpoints/catalog` 是重定向入口，需要验证最终目的地。其他页面应结合导航、后台路由和实际行为判断支持状态，不凭名称猜测。

初次设计盘点有 49 个 `.spec.ts` 文件；默认 Playwright 列出 48 个文件、151 项测试。真实供应商文件默认不注册用例；无端点场景需要特殊夹具，默认会跳过。151 是历史用例发现数，不是执行通过数，也不等于本方案覆盖已经充分；每轮重新盘点。

### 1.1 本次修订：可见的按角色连续任务模式

用户主验收采用 RPA 风格：可见窗口、一个角色一个独立上下文、每条角色任务线开始时只登录一次。同一角色连续完成多个业务任务，期间不清 cookie、不重建上下文、不偷偷补登录；刷新、前进后退和页面切换必须保持身份。只有退出／过期／SSO 专项明确要求时才再次认证，且打印原因。一个用户拥有多个角色时不借用其权限作为单一角色夹具。

逐例隔离的现有 E2E 保留为回归层，不能直接拼接并称为角色连续验收。主验收以页面点击、输入、选择、提交为主；API 用于夹具准备、权限负向探测和独立核对，必须在记录中标明，不能替代待验 UI 功能。清理接口与清理页面验收也分别标记。

每一步在动作前及动作后实时输出，并同步写入任务记录：

```text
[角色 开始] 组织A管理员｜会话 org-A-admin｜任务线 ORG
[任务 待执行 ORG-03] 为团队A1分配预算，验证不能超过组织可分配额度
[任务 开始 ORG-03][步骤 02/06] 修改预算并提交
[任务 完成 ORG-03] 页面回读、后台结果、真实调用限制均符合预期
[任务 开始 ORG-04] 调整成员归属并验证旧权限撤销
[任务 失败 ORG-04] 预期跨团队拒绝，实际允许｜证据编号 evidence-042
[任务 阻塞 ORG-05] 依赖 ORG-04 的成员迁移结果，不继续消费错误状态
```

完整计划在角色开始前打印；执行时逐项打印，不只输出长测试的总标题。失败后保留当前页面及证据，独立任务继续，同一状态依赖任务明确阻塞；禁止自动重新登录掩盖会话错误。可配置展示节奏方便观察，但通过判据必须依赖状态而非延时。主验收记录语言、角色、资源、会话、步骤、耗时、实际／预期、证据及清理状态，不打印秘密。

## 2. 环境、授权与隔离

- 默认使用真实 Chromium、production 控制台、真实网关、隔离 PostgreSQL schema 和本地协议供应商。
- 不对当前开发实例进行写入测试；不终止用户已有服务或关闭无关标签页。现有开发页面仅可用于明确标记的只读观察。
- 每轮资源使用独立 run ID；记录资源 ID、归属、创建者、配置原值及清理责任。
- 平台管理员、组织管理员、团队管理员和成员分别使用独立浏览器上下文，不共享登录 cookie。
- Redis 专项使用独立实例；缓存清空只能针对本轮隔离环境，禁止清空共享 Redis。
- 保留现有 browser/acceptance 锁；共享 `.e2e/current` 的阶段必须串行，下一阶段开始前归档证据。
- 禁止用 `make testdata` 建临时测试数据；该入口会清空共享数据。
- 默认不运行 `make e2e`、`make e2e-all`、`--live` 或真实供应商调用；费用、凭据和外部范围须单独授权。
- 数据库、浏览器或必要工具缺失必须记录阻塞，不得把 skip 或无用例注册算作成功。

## 3. 用户视角

| 身份／视角 | 用户目标 | 必须验证的边界 |
| --- | --- | --- |
| 未登录访客 | 阅读帮助、找到登录入口 | 受保护页面拒绝；匿名文档可读；错误登录不残留会话 |
| 平台管理员 | 配置模型、租户、路由、安全策略 | 能完成授权管理；变更实际生效；秘密不回显 |
| 平台只读管理员 | 审阅配置与运行情况 | 按权限契约获得只读范围；写操作和产生调用费用的动作不可用 |
| 组织 A 管理员 | 管理本组织团队、用户与分配 | 不越权访问组织 B；组织角色不冒充平台角色 |
| 团队 A1 管理员 | 管理团队成员、项目与额度 | 不越权访问同组织 A2 或其他组织；不能扩大上级授权 |
| 普通团队成员 | 创建个人密钥、使用授权模型 | 只见授权数据；不能管理他人、模型部署或平台设置 |
| 无团队用户 | 使用个人密钥和自身额度 | 不强制虚构团队归属；不能获得全局范围 |
| 普通只读用户 | 查看自身资源与用量 | 不因页面隐藏按钮而漏掉后台写权限检查 |
| 组织 B 对照用户 | 使用隔离的另一套资源 | 列表、详情、搜索、日志、导出均不泄漏 A 的数据 |
| 被停用／会话失效用户 | 获得明确的拒绝与重新登录提示 | 旧会话及密钥按各自契约失效，不继续访问或调用 |

创建角色夹具时通过真实成员关系接口核对权限，不能只修改前端角色标签。额度为角色以外的独立约束。组织管理员的统计范围按接口契约验证，不预设所有用量接口都提供组织全量数据。

## 4. 任务线与验收标准

每条任务线至少包含正常、边界、失败和恢复；每个有写入的流程均验证取消不保存、刷新回读、实际生效和清理。现有 spec 是复用入口，缺失项必须显式登记，不能因文件名相似就认为已覆盖。

### 共享夹具和执行依赖

以组织 A（A1、A2 两个团队）和组织 B（B1 团队）构造最小跨组织及同组织跨团队对照，各有不同用户、项目、密钥、模型授权和日志。另设无团队用户、两类只读用户和被停用用户。

执行顺序：环境预检 → T01 → T02/T04 资源基础 → T03 权限 → T05/T06/T07/T08 调用 → T09/T10/T11 策略与限制 → T12 对账 → T13/T14/T15 设置 → T16/T17 全入口复核 → 清理核对。

每条任务线自己准备必要资源，不依赖上一条恰好成功或共享其可变对象。上面的顺序用于理解和定位，不允许一个失败导致独立任务全部跳过。注销、停用、超限、默认护栏、缓存清空等影响面较大的场景使用独立夹具或结束即恢复。

### 4.2 金额额度、RPM、TPM：独立约束矩阵

逐一核对组织、团队、项目、用户／成员、密钥等实际存在的约束层；平台全局限制和个人预算若存在也纳入。先从实现及接口契约确认作用域和继承方式，不假定所有层都支持同样字段。每次只压低一个约束，其余留足余量，证明拒绝来自目标层，再验证两层同时受限及有效优先级。

| 维度 | 必须执行的验证 | 可观察的通过条件 |
| --- | --- | --- |
| 字段与分配 | 缺省／空／零／负数／小数／超大／非法字符；超配、调低上级、重复提交、取消 | 以字段契约解释零与无限制；非法写入无部分保存；刷新与接口一致 |
| 金额边界 | 余额大于、等于、小于单次确定性成本；耗尽后再调用；有权主体提高预算后重试 | 以实现的预留／结算规则判定边界；拒绝不出上游；恢复可调用且不补记拒绝费用 |
| 并发金额 | N 个同步触发请求竞争小额余额；成功／失败／取消／超时混合 | 预留不透支；最终费用等于实际可计费调用之和；失败不永久占额；无重复回填 |
| RPM | 独立夹具设置 L=3，窗口内 3 次允许、第 4 次拒绝；其他主体对照；窗口到期重试 | 达到契约计数边界，拒绝原因明确；不同用户／团队不会错误共用；观察到恢复 |
| TPM | 固定输入输出用量，阈值以下／正好／越界；流式回填；超大请求；并发 | 按实现区分预估占用与实际用量；拒绝及释放正确；金额剩余不代表 TPM 可放行 |
| 相互作用 | 仅预算不足／仅 RPM／仅 TPM／同时不足；提高一个仍受另一个约束；密钥轮换与用户聚合 | 错误类别及有效约束可解释；不能换密钥绕过用户或团队级限制 |
| 生命周期 | 修改限额、移入移出团队、停用、配额周期切换／重置（若支持）、服务重启 | 新请求按最新规则，历史账务不重写；Redis 热状态与持久化不漂移 |

金额使用本地上游固定 token 与固定价格，按最小记账单位或明确舍入规则计算期望，不用随机模型输出；RPM/TPM 使用专属主体和 Redis。真实浏览器验收至少通过 UI 配置限制、触发请求、看到拒绝并恢复；精确并发／时钟边界由后台回归补充并单列，不能伪称 RPA 点击覆盖全部压力边界。

### 4.3 计费计量：每笔请求可复核

冻结本轮价目及计费语义：输入／输出／缓存 token 单价、媒体计价、币种、舍入精度、失败是否计量、重试计费对象、归属和幂等键。标准 token 场景期望为 `输入token×输入价 + 输出token×输出价`；缓存及媒体按实际契约独立计算，不套用普通公式。

每笔关联页面请求 → call/request ID → 上游实际收到的请求与次数 → 持久化 usage／price snapshot → 用户／项目／团队／组织／密钥归属 → 列表／详情／汇总／CSV。每个有权视角核对同一笔数据；没有组织聚合权限的接口验证拒绝或自身范围，不强求全量汇总。至少执行：成功、失败、超时、SSE 中断、客户端取消、护栏拦截脱敏、缓存命中、重试回退、续接、媒体完成失败、重复轮询和队列重投。价格修改只影响契约规定的新请求，历史快照不漂移。

队列专项验证 Redis 暂不可用、数据库提交失败、确认失败及恢复后最终一致且不重计；只在隔离服务注入故障。记录本轮新增数据的基线差值，不拿整个数据库累计值当断言。分页全量遍历无重复无缺失，筛选与 CSV 行集一致，时区日期边界及跨日费用与查询契约一致。

### 4.4 SSO 与 SCIM：配置、真实协议、权限收回三层验收

SSO 和 SCIM 分开建数、分开执行、分开清理，不能让 SSO 首步失败阻止所有 SCIM 覆盖。SSO 使用本地确定性 IdP，浏览器真实点击登录入口、跳转授权、回调建立会话，再通过业务页面核对身份。验证 issuer／audience／签名及 state／nonce 等仅限实际支持协议；未实现的 OIDC／SAML 能力列为不支持，不凭表单推断支持。回调错误有可理解提示，不能静默给默认管理员身份。SSO 删除后有剩余授权状态／映射／审计时按明确依赖契约拒绝或清理，不能返回不明 500。

SCIM 协议写入由本地目录客户端发起，这是外部系统动作而非虚构 UI 操作；浏览器负责创建连接、启停、映射配置以及查看同步后用户和团队。验证真实支持的 Users／Groups 操作、PUT／PATCH、分页／过滤、重复 externalId／冲突、active=false、令牌轮换和跨连接隔离。未知字段及不支持操作按契约明确拒绝。

身份关联专项：SCIM 先建用户 → SSO 登录是否关联同一人；重复同步／登录不复制账号；身份匹配按稳定标识和租户边界，不能仅凭可修改显示名或邮件绕过隔离。SCIM 撤组／停用 → 已登录上下文与已发密钥按声明的失效时效验证；同步失败不可留下半更新的越权成员。删除顺序覆盖用户／组／映射／连接／组织以及反向删除拒绝，业务清理失败即单列失败，即使最后 schema 清理成功。

没有本地 IdP 或目录夹具时，配置 UI 和后台协议可各自测试，但完整浏览器企业闭环仍为阻塞；真实企业租户另行授权。

### 4.5 执行批次、完整性与失败处理

先冻结权限／功能契约及覆盖表，再准备 A/A1/A2 与 B/B1、个人用户及专属模型、价格、配额。按角色批次可见执行；每个角色有独立窗口／上下文和会话名称，非当前角色不操作。管理员前置建数不算其他角色完成 UI 管理。LIMIT／BILL／SSO／SCIM 专项保留参与角色的上下文，跨角色切换是切换已存在会话，不每步重新登录。

每任务记录设计／实现／已执行／证据完整四种覆盖阶段。108 节点必须逐个落到可执行例、业务断言及资源清理；计划完整不等于实现完整，已有 151 例也不代表覆盖 108 节点。依赖图使失败只阻塞必要分支，独立任务继续；错误状态不得传给后续计费统计。角色会话失效作为失败留证，不自动修复为成功。中断后先核对会话和资源，明确标记恢复点，不能靠重新跑登录宣称会话连续。

## 5. 跨场景检查

- 中英文：所有在范围内的页面、错误、空态、状态和无障碍名称分别验证；动态值通过插值正确显示。默认提示词、示例请求和 curl 保持英文，用户原始中英文正文不被翻译。
- 交互：键盘操作、焦点、必填、错误输入、无结果、分页首尾、重复提交、取消、未保存离开、刷新和浏览器前进后退。
- 布局：桌面全流程；窄屏覆盖登录、导航、密钥、聊天、模型／回退弹窗和日志详情。大表格可以合理横向滚动，但操作入口不能消失。
- 异常：本地协议上游制造超时、拒绝、非法正文、SSE 中断和异步失败；产品不能静默成功、丢失错误或无限加载。错误注入需隔离，预期错误只豁免对应请求，其他异常仍失败。
- 保密：报告、截图、URL 和日志禁止记录密码、令牌、API key、企业凭据；只记录安全哈希及资源 ID。
- 清理：取消、失败或中断也执行 finally／teardown；业务删除后以 UI、真实后台和调用拒绝核对；schema 删除、独立服务退出和配置恢复单独验收。

不把所有输入做笛卡尔积：每条业务线覆盖最贴近实现的正常／边界／失败，在浏览器层验证用户可见闭环；每项权限规则必须有允许和拒绝对照。金额边界由确定性用量夹具构造，权重不能用少量随机样本声称比例正确。

## 6. 证据标准与用例格式

每个用例包含：编号、任务线、角色及归属、语言、视口、前置条件、具体 UI 步骤、预期、实际、接口契约、持久化断言、数据面断言、资源／call ID、证据、状态和清理结果。
