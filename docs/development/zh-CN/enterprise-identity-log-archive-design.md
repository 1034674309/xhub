- 已实现连接绑定组织、一次性 SCIM Bearer 凭据、连接启停和基础 Users/Groups 的 GET/POST/PUT/DELETE、稳定分页与精确过滤。凭据仅保存哈希。
- 已实现组到同组织团队的显式映射、数字优先级、有效当前团队保持、人工团队覆盖、人工固定无团队以及单用户恢复自动分配。组与团队不是同一个资源。

## 1. 目标与范围

### 当前版本接入步骤

1. 服务部署到公网 HTTPS 源，例如 `https://console.example.com`；需自行配置 DNS、证书和反向代理，`http://127.0.0.1:3000` 仅用于本地管理，不能提供给企业平台。服务端 Master Key 必须稳定且至少 32 字符，用于保护 SSO/七牛密钥；变更前须安排密文迁移。
2. 在 `/admin-panel` 选择已创建组织，填写目录名称、创建连接并安全保存一次性凭据。填写 XHub 公开源，将每个连接生成的 `/scim/v2/connections/{id}` 完整地址和 Bearer 凭据登记到身份平台的 SCIM 2.0 预配配置中；启用连接。SCIM 是平台推送，不需要配置平台目录域名或 LDAP 域名。
3. 配置平台的 externalId/userName/active 和组映射，先推送测试用户/组；在 XHub 选择组及同组织团队并保存映射。非部门组无需映射，多组命中遵循人工覆盖、有效当前团队保持、稳定优先级选择。
4. 在平台创建 OIDC Web 应用，获取包含租户路径的 issuer、Client ID/secret，支持 Code + PKCE S256。用公开源生成 `/auth/enterprise/callback` 和 `/ui/login`；回调原样登记在平台，两个地址同源 HTTPS。公开登录入口走控制台 `/gw/auth/enterprise/{id}/start`，确保 cookie 与回调同源。
5. 稳定身份 claim 必须与 SCIM externalId 同源同值，例如按租户配置 oid/sub；不能假设平台的 sub 一定等于 SCIM externalId。先保存停用配置，再启用，随后从登录页完成测试登录。当前不会自动创建未同步用户或按邮箱合并，保留本地管理员应急登录。
6. 创建私有 Kodo 空间，选择其真实区域，填写专用 AK/SK、空间和前缀；保持停用保存，执行探针上传/清理测试，成功后启用。不需下载域名。新账务及结算更新异步归档，正文/别名变化不生成事件；停用只停止捕获新事件，已捕获积压仍写原版本目标。启用前历史记录不会自动补存。
7. 加载归档状态查看 pending/processing/failed/done；外部不可用不阻塞模型账务，失败自动退避，达到十次后需管理员重试。PostgreSQL 始终保留权威账务，不删除历史数据。

真实验收需租户管理员完成应用配置和推送，并提供七牛测试空间权限；本地 TLS 协议夹具与离线失败测试不能替代 Entra/Okta/七牛账号互操作验收。

在现有管理员页面增加企业身份和计费日志归档能力：

1. 使用公开、成熟的 OIDC 协议完成 SSO 登录。
2. 使用 SCIM 2.0 同步用户、企业组及成员关系，映射到 XHub 组织和团队。
3. 保持用户最多属于一个团队；多组命中时自动选择团队，管理员可覆盖。
4. 将计费计量日志可靠归档到七牛 Kodo，保持数据库为账务权威来源。
5. 提供配置验证、错误状态、审计、凭据保护和故障恢复。

第一期不包含 SAML、企业目录主动拉取、嵌套组展开、多团队计费、自定义组织层级协议、七牛日志检索服务以及自动删除数据库历史账务。SCIM 推送与 OIDC 登录不依赖七牛归档是否可用。

## 3. 核心决策

| 事项 | 第一期开关或规则 | 设计原因 |
| --- | --- | --- |
| SSO | 通用 OIDC Authorization Code + PKCE | 使用成熟身份协议，不为每家厂商单独定义登录协议 |
| 目录同步 | SCIM 2.0，由企业身份平台推送 | 用户与组生命周期采用公开标准 |
| 组织 | 创建连接时绑定已存在的组织 | SCIM 没有标准的组织树资源 |
| 团队 | 显式映射 SCIM Group 到 XHub 团队 | 避免所有员工、地点等非计费组影响归属 |
| 多组命中 | 人工覆盖 > 保持有效当前团队 > 按映射优先级选择 | 防止目录返回顺序变化引起团队抖动 |
| 自动开户 | SCIM 创建；目录管理模式关闭 SSO 自动开户 | 避免登录绕过同步与开通策略 |
| 平台管理员 | 仅本地显式授予，不从企业组自动映射 | 防止外部组或 claim 造成平台提权 |
| 日志归档 | 七牛 Kodo 私有空间，后台批量上传 | 不阻塞模型请求，不改变账务权威来源 |
| 数据库清理 | 第一期关闭自动清理 | 先验证完整性与恢复能力，再启用生命周期迁移 |

## 4. 标准与互操作边界

- OIDC：[OpenID Connect Core 1.0](https://openid.net/specs/openid-connect-core-1_0.html)。
- PKCE：[RFC 7636](https://www.rfc-editor.org/rfc/rfc7636)。
- SCIM 数据模型：[RFC 7643](https://www.rfc-editor.org/rfc/rfc7643)。
- SCIM 协议：[RFC 7644](https://www.rfc-editor.org/rfc/rfc7644)。

Microsoft Entra ID、Okta 等主流身份平台采用这类企业接入组合，但具体应用配置、属性映射和协议子集仍须分别验收。不能仅因实现了标准端点就宣称通过所有厂商认证。飞书、钉钉、企业微信等入口是否适用通用 OIDC，必须核实其实际产品能力，必要时通过身份代理接入。

SCIM Enterprise User 扩展的 organization、department 是用户属性，不是独立组织资源。第一期提供“连接绑定组织、Group 映射团队、User 映射用户”，不声称支持任意组织树同步。新增组织由平台管理员完成；自动创建组织属于后续专门设计。

## 6. SSO 登录设计

### 6.1 配置与状态

每个企业连接保存名称、组织、OIDC issuer、client_id、加密 client_secret、scope、身份关联 claim、本地登录策略及可选域名限制。第一期每个组织一个权威目录和对应 OIDC 连接，平台可配置多个组织连接。已存在本地账号跨连接关联需显式批准，不默认合并。

回调地址根据受信任的公开控制台/后台地址生成；不根据不受信任 Host 头推导。公开登录配置只返回已启用连接的 ID、显示名及登录入口，不泄露秘密、目录成员或映射配置。

状态采用 draft、verified、enabled、disabled；记录验证的配置版本。修改 issuer、client_id、secret、身份关联规则等关键参数后，旧验证不再适用，新版本须重新验证后启用。

默认保留本地登录，关闭 SSO 即时开户。关闭普通本地登录前，要求当前配置版本完成真实测试登录，并确认受控的本地应急管理员恢复途径。SSO 故障不得自动开放普通密码登录。应急恢复需审计、限速及明确运维授权，不新增公开绕过入口。

### 6.2 身份关联与登录流程

1. 用户选择企业连接，后台创建短时、单次使用登录事务，绑定连接、state、nonce、PKCE 与安全返回地址。
2. 身份平台完成验证，后台交换授权码并校验 ID Token 签名、issuer、audience/azp、有效期、nonce 及事务归属。
3. 用 (connection_id, issuer, sub) 查询外部登录身份。首次关联须匹配该连接指定的稳定企业标识与已有 SCIM 身份。
4. 检查本地用户、连接与目录身份均允许访问，检查团队归属与当前权限，签发既有 XHub 会话。
5. 记录成功或失败审计，不记录授权码、token、secret 或敏感 claim 原文。

SCIM externalId 与 OIDC sub 不保证相同。连接必须配置可验证的共同稳定标识；没有共同标识时由管理员显式关联，不能静默依靠邮箱合并。测试登录显示经过脱敏的关联结果，不自动开户、授予角色或改变团队。邮箱更新不改变已经建立的稳定身份绑定。

同邮箱冲突、跨组织关联冲突、未同步账号、停用账号、缺失关联 claim 分别返回可定位错误。域名白名单仅作为附加限制，不能代替 token 验证及账号关联。没有团队不自动获得预算或推理权限。

### 6.3 安全和会话撤销

禁止开放重定向和跨连接 callback 混用；PKCE 使用 S256。限制认证事务有效期、一次性消费及登录频率。OIDC discovery/JWKS 请求设置超时、响应大小和缓存，校验 HTTPS 地址、重定向及解析后的目标 IP，阻止未授权内网、回环和云元数据访问。

目录禁用用户时，在事务中更新状态与 session_version，并撤销受影响密钥；所有后续受保护请求重查有效性，不只等待浏览器 cookie 过期。企业 IdP 停用到 SCIM 推送到达之前存在延迟窗口，第一期不承诺实时目录撤销。平台管理员账号受本地最后管理员保护，不能被同步规则意外停用或降权。

## 7. SCIM 目录同步设计

### 7.1 连接与认证

每个连接绑定唯一组织，使用随机高强度 Bearer token，明文仅创建/轮换时展示一次，后台只保存验证所需哈希。token 不能调用推理或管理接口；组织范围由后台连接记录决定，客户端字段不能改变它。

建议基址为 /scim/v2/connections/{connection_id}；该基址下提供标准资源路径。连接停用后拒绝新同步，不自动删除已同步用户；停止同步与撤销用户访问是两个独立操作。轮换默认立即失效旧凭据；如提供过渡窗口，必须明确期限、旧凭据状态与审计。

### 7.2 资源与协议契约

| 资源 | 第一期开通能力 |
| --- | --- |
| /Users | GET 列表/详情、POST、PUT、PATCH、DELETE |
| /Groups | GET 列表/详情、POST、PUT、PATCH、DELETE，用户成员增删 |
| /ServiceProviderConfig | 声明实际支持的 filter、patch、认证等能力 |
| /Schemas | Core User、Group 与实际支持的扩展 |
| /ResourceTypes | User、Group 定义 |

遵守 application/scim+json、ListResponse、startIndex/count 分页、标准 Error schema、HTTP 状态码与 PATCH 原子语义。支持厂商常用 userName/externalId 精确过滤与成员操作；支持的过滤语法、属性及上限须明确声明，未支持能力返回标准错误，不能忽略条件后返回全量。PUT 的替换语义及只读属性保护需遵循标准，不将 PUT 当部分更新。

资源 id 由 XHub 分配并保持稳定，externalId 在连接内关联外部目录；userName 规范化后唯一。同一个外部身份重复提交不得重复创建账户；冲突返回 409 等标准响应，不能将两个不同身份因邮箱相同合并。第一期不支持 Bulk、嵌套 Group 成员或自定义组织资源，ServiceProviderConfig 如实声明。

成员未知时拒绝该变更并返回标准错误，不凭成员邮箱临时创建用户。客户端先创建 User 再同步 Group。DELETE User 采用访问停用/逻辑删除，不物理删除历史账务；重复删除按标准返回不存在，重新开通由显式受控流程处理。

### 7.3 数据所有权

目录管理字段：外部身份、用户目录状态、配置中声明受目录管理的邮箱/姓名、企业组及成员关系。本地管理字段：平台角色、预算、模型权限、密钥、组映射、人工团队覆盖。SCIM 不能授予平台管理员、任意预算或指定其他组织。

第一期新增目录用户默认普通角色、单连接专属管理；已有本地用户纳入目录前需要管理员确认字段所有权和停用影响。若已有身份不能安全归入同一组织，保留原状并报告冲突。以后支持一个本地账号多个目录身份时，必须另行定义“撤销某组织访问”与“停用全局用户”，不可直接复用全局禁用。

每个 SCIM 请求只代表对应资源的更新，不代表全目录快照。没有收到用户或组的更新不等于删除；只依据明确 PUT/PATCH/DELETE 更新已持久化的关系。

## 8. 单团队自动分配与人工覆盖

### 8.1 已确认的规则

用显式排序的组映射定义“第一个”，绝不依赖 SCIM 数组顺序、请求到达顺序或数据库自然顺序。映射团队必须属于连接绑定组织；第一期一个企业组映射一个团队，多个组可以映射同一团队。

每个用户的有效候选集 C 为：已持久化组成员关系中，匹配当前启用映射且目标团队可用的团队。排序键为映射优先级及固定映射 ID；界面保存时保证优先级顺序明确。

| 条件 | 结果 |
| --- | --- |
| 存在有效人工覆盖 | 保留管理员指定团队，SCIM 不覆盖 |
| 自动分配且当前团队仍在 C 中 | 保持当前团队 |
| 自动分配且当前团队不在 C 中，C 非空 | 选优先级最高的候选团队 |
| 自动分配且 C 为空，配置了有效默认团队 | 使用默认团队 |
| 自动分配且 C 为空，无有效默认团队 | 无团队，不自动获得推理权限 |
| 用户被目录禁用 | 禁止访问；人工覆盖不能绕过 |

管理员可以显式固定为无团队，含义是人工覆盖而非恢复自动分配。人工目标团队被删除/停用或越出连接组织时，保持 manual 状态但清空不可用归属并告警，不静默切回自动。删除团队须先通过已有依赖和权限检查。

### 8.2 来源展示与重算

用户详情显示 effective_team、assignment_mode（auto/manual）、选中映射、分配原因、修改人和时间；组列表保留完整企业成员关系，不因只选一个团队而丢失其他组。管理员修改默认为 manual，并提供“恢复自动分配”。

调整优先级不迁移仍符合条件的现有自动用户。显式重新分配分两步：预览差异，再确认执行；仅对 auto 用户忽略“保持当前团队”规则，不覆盖 manual。预览携带配置及成员关系版本，执行时版本变化则要求重新预览，避免确认过期结果。

首次开通时成员关系可能分多次到达，先按当前已知关系分配，后续保持有效归属；不承诺自动得到尚未收到的完整目录中的最高优先级团队。目录初始开通完成后可执行一次重算预览；需要精确首轮分配时，先保持连接访问关闭，完成目录推送和预览，再开启 SSO 访问。

### 8.3 示例与边界

优先级：研发部 → 研发团队，北京办公室 → 北京团队；所有员工不映射。首次已知两个组时选择研发团队，目录交换组顺序不改变结果；管理员改为北京团队后，后续同步不覆盖；恢复自动分配后按已知候选重新选择。

自动用户退出研发组且仍在北京组时迁移到北京团队；若仍通过另一个组命中研发团队则不迁移。旧团队没有有效候选时才使用下一团队或默认团队。不得因归属变为无团队而获得独立个人预算作为隐式绕过。

### 8.4 原子性、权限与账务

组成员变化、归属选择、依赖密钥撤销、权限缓存失效及审计在可行范围内同一事务完成，按用户锁串行化人工编辑和同步。并发预算分配仍服从已有额度不变量；迁移失败则回滚对应请求，不部分迁移。大组采用有界请求大小，后续批处理需另行定义原子边界，不能暗中截断成员。

归属变更不修改历史账单。已开始请求和异步任务沿用初始计费归属；新请求使用新归属。旧团队绑定的个人密钥按现有撤销规则处理，不自动改绑；团队服务密钥不属于用户迁移对象。新团队的权限与预算重新校验，不继承旧团队授权，也不由 SCIM 自动分配额度。

## 9. 七牛 Kodo 计费计量日志归档

已确认：此处“存放到七牛云”指将日志文件写入七牛云 Kodo 对象存储的私有 bucket，不接入七牛日志检索服务。计费计量记录按批次形成 JSONL.gz 文件上传；数据库继续承担在线计费与查询，云存储承担文件保存。本文的“归档”均指这一对象存储行为。

### 9.1 权威来源与配置

数据库保留计费事件、聚合、额度和权限的权威地位，Redis 既有实时链路不变。Kodo 仅保存归档副本；第一期不将在线日志查询自动改为扫描云对象，也不把对象上传作为费用结算条件。

配置包含私有 bucket、区域、对象前缀、加密 AK/SK、归档类别、批次阈值、运行状态及配置版本。默认只归档开启后的计费计量记录，请求/响应正文默认关闭。建议初始批次上限为 5 分钟或 10 MiB 未压缩数据，先到先触发；参数是实现建议，需压测后确认，超大单条记录单独处理并限制正文体积。

测试连接仅使用隔离的测试对象前缀，完成上传、读取校验和删除；若凭据无删除权限，明确报告清理失败，不声称全部通过。生产凭据采用最小权限，测试与历史补归档不得覆盖已有用户对象。

### 9.2 数据格式与版本

归档格式为 UTF-8 JSONL.gz，字段包含 schema_version、event_id、request_id、event_version、event_type、任务状态、发生/结算时间、初始组织/团队/用户/项目/密钥 ID、模型与部署、计量单位及数量、币种、金额/精确金额表示、计价快照、HTTP 状态及错误分类。不得把所有媒体计量强行转换为 token；保持现有价格精度且不在导出时重新计价。

对象键包含受控前缀、连接/配置版本、事件日期和固定 batch_id；清单保存行数、事件范围、摘要及格式版本。密钥 ID 是内部标识，不能包含明文 API Key。每批次内容冻结后才能上传，相同对象键不能用于不同内容。

异步任务初建、状态变更与最终结算为不同版本事件，逻辑去重键为 (request_id, event_version)，不是只导出 request_id 一次。消费者以版本处理更新；重放不能再次增加费用。最终结算记录明确标记，归档必须可恢复最终状态及初始归属。

### 9.3 可靠归档链路

1. 成功账务事务内同时写入不可变的待归档事件快照（outbox）；事务失败不产生可导出事件。
2. Worker 领取带租约任务，冻结批次及 manifest，以配置版本绑定目标 bucket 和凭据引用。
3. 压缩并上传固定对象键，进行大小/摘要校验；不能把 ETag 一概当作内容 SHA-256。
4. 数据库事务标记批次 verified 和对应事件 archived。
5. 超时、崩溃或重复领取恢复同一批次；已上传未确认时先校验现有对象，再确认，不生成新逻辑批次。

数据库与对象存储之间不能实现本地单事务的 exactly-once，采用至少一次处理、稳定对象键、不可变内容和事件去重，保证逻辑归档不重计。多实例使用租约、续租和 fencing/version 条件更新，防止过期 Worker 错误确认任务。

失败使用有上限退避和抖动；达到重试阈值进入 failed 状态，但保留事件和批次，允许管理员重试。状态为 pending、leased、uploaded、verified、failed；uploaded 不等于安全可清理。变更目标仅影响新事件，旧积压按原配置版本处理；迁移积压须独立预览确认。旧凭据引用在依赖批次完成前不得静默销毁。

关闭归档停止产生新归档任务，已排队任务默认继续排空；暂停 Worker 是单独操作。删除配置必须先处理依赖批次，不自动删除云端历史对象。若 outbox 写入失败，账务事务不得悄悄跳过归档要求；错误遵循现有可靠计费重试链路，不将已执行上游请求伪装为未执行。

### 9.4 正文、保留与历史补归档

正文归档同时受提示词保存策略与归档类别控制；禁存时不在 outbox 偷偷保存正文。敏感字段在形成快照前脱敏，禁止记录 Authorization、cookie、API Key 和提供方秘密。脱敏失败时保留允许的计量元数据并标记正文省略原因。

第一期无自动数据库清理。后续只有已验证归档、超过保留期、最终态并通过必要的查询/法务策略检查的明细或正文才可清理；预算累计、价格依据和必要账务摘要不能随之删除。云端期限依赖 Kodo bucket 生命周期实际配置，页面不能仅保存一个天数就宣称云对象会被自动删除。归档也不替代完整数据库备份。

历史补归档使用日期范围、预计数量和截止水位预览，确认后生成独立任务；与实时 outbox 使用相同逻辑去重，处理中任务完成后仍导出最终结算版本。用户撤回正文存储授权后的历史补归档不额外恢复禁存正文。

### 9.5 故障、下载与可观察性

七牛故障不直接阻塞模型请求或更改已确认费用；归档任务留库并告警。设定 outbox 容量、磁盘与数据库水位阈值，提供积压量、最旧年龄、最近成功、失败分类及重试状态。不能承诺无限期故障下无限积压；临界水位触发运维处置，达到存储硬上限遵循明确失败策略，禁止静默丢账或自动删除未归档数据。

第一期归档下载仅平台管理员可用，先由 XHub 鉴权，再签发短期私有下载链接，不记录签名 URL 到普通日志。组织级下载后续必须重新核对对象分区和权限，不向组织用户暴露含其他组织数据的共享批次。

## 10. 拟议数据模型与接口

### 10.1 数据模型

| 模型 | 关键字段与约束 |
| --- | --- |
| enterprise_connections | org_id、OIDC 参数、状态、配置版本、加密秘密引用；组织权威连接唯一 |
| scim_credentials | connection_id、token_hash、状态、到期/轮换信息 |
| external_identities | connection_id、SCIM id/externalId、issuer/sub、user_id、目录状态；稳定标识唯一 |
| directory_groups / members | 连接内组 ID、externalId、成员关系、资源版本；成员去重 |
| group_team_mappings | group_id、team_id、priority、enabled、版本；目标组织一致 |
| user_team_assignments | user_id、auto/manual、selected_mapping、人工覆盖、原因、版本；单团队约束不变 |
| archive_configs / versions | bucket、region、prefix、类别、加密凭据引用、不可变配置版本 |
| archive_outbox | 事件去重键、不可变快照、配置版本、批次和处理状态 |
| archive_batches | batch_id、对象键、manifest、摘要、租约、重试次数、校验状态 |

具体表名及是否复用现有配置/审计表由实施时决定。迁移需处理唯一索引、事务锁、回填、版本更新及回滚；禁止直接把目录组成员关系当作 XHub 多团队成员关系。

### 10.2 管理接口与公开边界

拟议管理接口按 /admin/enterprise-connections、其 /validate、/group-mappings、/assignment-preview、/assignment-apply，以及 /admin/log-archives 下的 /test、/status、/retry、/backfill 等资源组织；用户团队人工覆盖在现有用户管理边界扩展。最终路径需遵守现有网关规范并补充接口契约。

公开端仅提供已启用登录选项与 OIDC begin/callback；SCIM 端只认组织范围同步凭据。管理接口统一校验平台管理员会话、CSRF/Origin 防护及权限；所有读取秘密只返回 configured 状态，不返回加密值或原文。配置和操作返回机器可识别错误码，由 UI 国际化显示。

## 11. 安全、审计与运维

OIDC secret 与七牛 SK 使用独立服务端加密主密钥，不复用用户密钥；部署时提供密钥管理和备份恢复说明，支持版本化轮换。SCIM token 只存哈希。禁止在浏览器持久存储或日志中泄露秘密。

记录连接变更、凭据轮换、登录失败、目录资源变更、人工覆盖、团队迁移、重算、归档重试与下载审计；包含操作者、来源、资源 ID、结果、关联请求和变更原因，不保存凭据。最后管理员、跨组织迁移、预算约束沿用现有安全不变量。

监控区分“最近收到同步请求”和“目录完全同步”；没有请求不等于目录同步失败，处理成功也不证明完整目录已推送。对反复 SCIM 错误、登录验证失败、归档积压和存储水位设置告警，阈值由部署配置决定。

## 12. 测试与验收计划

以下是实施阶段必须完成的测试，不是本文已经运行的结果。所有新增测试与辅助函数带中文注释，说明前置条件、目的、结果和清理；测试使用隔离数据，不覆盖用户目录或七牛对象。

| 分层 | 必须覆盖 |
| --- | --- |
| 单元/组件 | OIDC 配置、身份关联、非法 token/claim；SCIM filter/PATCH/PUT、错误格式；团队候选、稳定性、人工无团队、默认团队、恢复自动；事件版本、脱敏、批次摘要；中英文动态错误/状态及英文示例 |
| 后台 regression | 真实管理与 SCIM 路由权限、分页与资源契约、重复提交、同邮箱冲突、跨组织拒绝、并发人工/自动修改、事务回滚、最后管理员保护；计费/outbox 原子性、租约与崩溃恢复、异步结算和配置轮换 |
| 自动化 E2E | 管理员配置并测试 OIDC → SCIM 创建用户/组 → SSO 登录 → 展示团队与权限 → 发起推理 → 禁用后会话/密钥拒绝 → 数据清理 |
| 自动化 E2E | 多组按优先级首次分配 → 顺序变化不迁移 → 人工修改保持 → 恢复自动 → 原组移除自动迁移 → 重算预览与确认 → 历史/异步任务归属不变 |
| 自动化 E2E | 配置 Kodo → 测试对象清理 → 发起真实数据面请求 → 计费落库 → 上传并读取归档 → 对账与脱敏 → 上传失败/重启重试无重复费用 → 停用/补归档 |
| 自动化 E2E | zh-CN/en 切换、动态提示、失败/积压状态完整切换，用户原始输入不被翻译 |

本地可控 OIDC 服务必须真实签发与验证 token；SCIM 通过实际 HTTP 和数据库执行；Kodo 测试适配器可以提供隔离的真实 HTTP 对象读写，但不能据此声称七牛生产能力已验收。离线验证覆盖支持状态、权限、失败与降级；有凭据时另行运行真实七牛及企业身份平台兼容验收，上传测试对象后清理。默认不额外执行 Computer Use。

关键验收保证：一个用户最多一个有效团队；任何目录操作不能获得平台管理员；停用后新受保护请求失败；重放不重复开户/计费；七牛失败不改已确认账务；最终任务结算必有可归档版本；未验证归档不能触发清理。

## 13. 实施顺序与交付

1. 数据与安全基础：版本化连接、身份关联、秘密加密、审计及迁移。
2. SCIM：标准路由、用户/组同步、稳定团队分配、人工覆盖与重算。
3. OIDC：测试登录、已有同步账号关联、会话撤销与本地恢复。
4. Kodo：账务 outbox、批次上传、幂等恢复、运行状态与补归档。
5. 完整中英文 UI、单元/regression/E2E 和厂商兼容验收，按连接灰度启用。

功能可以分步开发，但不能在只完成表单或 mock 时宣称可用。每阶段交付记录修改文件、实际测试命令、通过/失败/跳过数、报告路径、清理结果及外部服务未覆盖边界。

回滚时先关闭新登录/同步或新归档入口，保留本地应急恢复、历史身份与账务数据；归档积压不删除。含新数据的迁移不得直接回滚删表，需要明确导出或兼容保留方案。

## 14. 后续扩展与待核实项

- 后续：SAML、企业组角色映射、SCIM 厂商高级能力、多目录统一账号、组织层级扩展、云端日志检索和安全明细清理。
- 实施前核实：首批接入身份平台及可用共同身份 claim，现有本地用户纳管名单，七牛区域/bucket/生命周期权限，容量阈值和保留要求。
- 这些待核实项不改变已确认的团队策略：有序选择、有效归属稳定、人工覆盖优先，目录停用不能被人工团队设置绕过。
